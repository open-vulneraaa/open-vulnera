# Language Model

### Model Selection

Specifies which language model to use. Check out the [models](/language-models/) section for a list of available models. Open Vulnera uses [LiteLLM](https://github.com/BerriAI/litellm) under the hood to support over 100+ models.

<CodeGroup>

```bash Terminal
vulnera --model "gpt-3.5-turbo"
```

```python Python
vulnera.llm.model = "gpt-3.5-turbo"
```

```yaml Profile
llm:
  model: gpt-3.5-turbo
```

</CodeGroup>

### Temperature

Sets the randomness level of the model's output. The default temperature is 0, you can set it to any value between 0 and 1. The higher the temperature, the more random and creative the output will be.

<CodeGroup>

```bash Terminal
vulnera --temperature 0.7
```

```python Python
vulnera.llm.temperature = 0.7
```

```yaml Profile
llm:
  temperature: 0.7
```

</CodeGroup>

### Context Window

Manually set the context window size in tokens for the model. For local models, using a smaller context window will use less RAM, which is more suitable for most devices.

<CodeGroup>

```bash Terminal

```

```python Python
vulnera.llm.context_window = 16000
```

```yaml Profile
llm:
  context_window: 16000
```

</CodeGroup>

### Execution Instructions

If `llm.supports_functions` is `False`, this value will be added to the system message. This parameter tells language models how to execute code. This can be set to an empty string or to `False` if you don't want to tell the LLM how to do this.

<CodeGroup>

````python Python
vulnera.llm.execution_instructions = "To execute code on the user's machine, write a markdown code block. Specify the language after the ```. You will receive the output. Use any programming language."
````

````python Profile
vulnera.llm.execution_instructions = "To execute code on the user's machine, write a markdown code block. Specify the language after the ```. You will receive the output. Use any programming language."
````

</CodeGroup>

# Vulnera

### Vision Mode

Enables vision mode, which adds some special instructions to the prompt and switches to `gpt-4o`.

<CodeGroup>
```bash Terminal
vulnera --vision
```

```python Python
vulnera.llm.model = "gpt-4o" # Any vision supporting model
vulnera.llm.supports_vision = True
vulnera.llm.supports_functions = True

vulnera.custom_instructions = """The user will show you an image of the code you write. You can view images directly.
For HTML: This will be run STATELESSLY. You may NEVER write '<!-- previous code here... --!>' or `<!-- header will go here -->` or anything like that. It is CRITICAL TO NEVER WRITE PLACEHOLDERS. Placeholders will BREAK it. You must write the FULL HTML CODE EVERY TIME. Therefore you cannot write HTML piecemeal—write all the HTML, CSS, and possibly Javascript **in one step, in one code block**. The user will help you review it visually.
If the user submits a filepath, you will also see the image. The filepath and user image will both be in the user's message.
If you use `plt.show()`, the resulting image will be sent to you. However, if you use `PIL.Image.show()`, the resulting image will NOT be sent to you."""
```

```yaml Profile
loop: True

llm:
  model: "gpt-4o"
  temperature: 0
  supports_vision: True
  supports_functions: True
  context_window: 110000
  max_tokens: 4096
  custom_instructions: >
    The user will show you an image of the code you write. You can view images directly.
    For HTML: This will be run STATELESSLY. You may NEVER write '<!-- previous code here... --!>' or `<!-- header will go here -->` or anything like that. It is CRITICAL TO NEVER WRITE PLACEHOLDERS. Placeholders will BREAK it. You must write the FULL HTML CODE EVERY TIME. Therefore you cannot write HTML piecemeal—write all the HTML, CSS, and possibly Javascript **in one step, in one code block**. The user will help you review it visually.
    If the user submits a filepath, you will also see the image. The filepath and user image will both be in the user's message.
    If you use `plt.show()`, the resulting image will be sent to you. However, if you use `PIL.Image.show()`, the resulting image will NOT be sent to you.
```

</CodeGroup>

### Messages

This property holds a list of `messages` between the user and the vulnera.

You can use it to restore a conversation:

```python
vulnera.chat("Hi! Can you print hello world?")

print(vulnera.messages)

# This would output:

# [
#    {
#       "role": "user",
#       "message": "Hi! Can you print hello world?"
#    },
#    {
#       "role": "assistant",
#       "message": "Sure!"
#    }
#    {
#       "role": "assistant",
#       "language": "python",
#       "code": "print('Hello, World!')",
#       "output": "Hello, World!"
#    }
# ]

#You can use this to restore `vulnera` to a previous conversation.
vulnera.messages = messages # A list that resembles the one above
```

### User Message Template

A template applied to the User's message. `{content}` will be replaced with the user's message, then sent to the language model.

<CodeGroup>

````python Python

````

```python Profile
vulnera.user_message_template = "{content}. Be concise, don't include anything unnecessary. Don't use placeholders, I can't edit code."
```

</CodeGroup>

# Computer

The .computer` object in `vulnera.computer` is a virtual.computer that the AI controls. Its primary interface/function is to execute code and return the output in real-time.

### Offline

Running the .computer` in offline mode will disable some online features, like the hosted [Computer API](https://api.openvulnera.com/). Inherits from `vulnera.offline`.

<CodeGroup>

```python Python
vulnera.computer.offline = True
```

```yaml Profile
computer.offline: True
```

</CodeGroup>

### Verbose

This is primarily used for debugging `vulnera.computer`. Inherits from `vulnera.verbose`.

<CodeGroup>

```python Python
vulnera.computer.verbose = True
```

```yaml Profile
computer.verbose: True
```

</CodeGroup>

### Emit Images

The `emit_images` attribute in `vulnera.computer` controls whether the.computer should emit images or not. This is inherited from `vulnera.llm.supports_vision`.

This is used for multimodel vs. text only models. Running .computer.display.view()` will return an actual screenshot for multimodal models if `emit_images` is True. If it's False, .computer.display.view()` will return all the text on the screen.

Many other functions of the.computer can produce image/text outputs, and this parameter controls that.

<CodeGroup>

```python Python
vulnera.computer.emit_images = True
```

```yaml Profile
computer.emit_images: True
```

</CodeGroup>

### Import Computer API

Include the.computer API in the system message. The default is False and won't import the.computer API automatically

<CodeGroup>

```python Python
vulnera.computer.import.computer_api = True
```

```yaml Profile
computer.import.computer_api: True
```
